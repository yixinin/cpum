# 2026-09-14

## 安装/运行方式改为 per-user + 仅服务提权

按用户要求把项目从「整台电脑安装 + 前台应用始终以管理员运行」改为「默认装到用户目录 + 仅安装服务时提权」：

- `src-tauri/tauri.conf.json`：`bundle.windows.nsis.installMode` 由 `perMachine` 改为 `currentUser`
  （安装目录变为 `%LOCALAPPDATA%\CPU Manager`，uninstall 注册表走 HKCU）。
- `src-tauri/app.manifest`：`requireAdministrator` → `asInvoker`，前台应用不再请求管理员权限。
- `src-tauri/installer-hooks.nsh`：整体重写
  - 规则目录从 `%ProgramData%\cpum` 改为 `%APPDATA%\com.eason.cpum`，并把旧目录（`%ProgramData%\cpum`、
    `%APPDATA%\cpum`）下的 `affinity_rules.json` / `probalance.json` 迁移过来。
  - 新增 `CpumRunElevatedBat` 宏：用 `powershell.exe Start-Process -Verb RunAs -Wait` 提权执行临时 bat，
    可等待并获取退出码（NSIS `ExecShell runas` 无法等待）。
  - 所有服务操作（`sc stop/config/start/delete`）先非提权尝试，只在服务确实存在时才提权，
    新装/无服务场景全程无 UAC。新增 `NSIS_HOOK_PREUNINSTALL`（非 `/UPDATE` 时停止并删除服务）。
- `src-tauri/src/lib.rs`：删除 `machine_rules_dir()`，新增 `rules_dir(app)`（基于
  `app.path().app_data_dir()`），probalance 五个命令都接入 `AppHandle`；`install_service` 用该函数取目录。
- `crates/cpum-service/src/main.rs`：`RULES_DIR` 重命名为 `LEGACY_RULES_DIR`（仅无参数启动时的回退）。
- 前端：i18n 新增 `serviceElevationHint`（中英双语），App.vue 服务弹窗展示；api.ts 注释更新。
- 文档：README.md / README.zh-CN.md / AGENTS.md 同步。

## 受保护进程的特权通道（服务代理 + UAC 兜底）

用户选择"装了服务走服务代理、没装服务走一次性 UAC 提权"：

- 新增 `crates/cpum-core/src/ipc.rs`：消息模式命名管道 `\\.\pipe\cpum-bridge-v1`，JSON 请求/响应，
  操作为 `ping` / `set_affinity` / `set_priority` / `apply_rules`。
  - 鉴权用共享密钥：`%APPDATA%\com.eason.cpum\bridge.token`（`ensure_token` 由 GUI 创建、
    `read_token` 由服务每次请求时读取），管道 DACL 用 SDDL `D:(A;;GA;;;SY)(A;;GRGW;;;IU)`。
    这样其他本地用户连得上管道但拿不到令牌。
  - `serve()` 在服务的后台线程阻塞；`Pipe(HANDLE)` 需要 `unsafe impl Send` 才能 move 进连接线程。
- `procwin::enable_debug_privilege()` 从 cpum-service 下沉到 cpum-core（服务与一次性 helper 都要用）。
- `cpum_service.exe` 新增一次性子命令 `--set-affinity <pid> <maskCsv> <strict|soft>`、
  `--set-priority <pid> <class|-> <io|-> <mem|->`，供 GUI 提权调用。
- GUI `lib.rs`：`set_process_affinity` / `set_process_priority` 先本地执行，命中
  `ERROR_ACCESS_DENIED`（判定子串 `0x80070005` / `Access is denied`）后依次走 bridge →
  `run_elevated_helper`（UAC）。`ELEVATION_FAILED` 记录失败 PID 防弹窗风暴。
  `apply_affinity_rules` 只在 `report.failed > 0` 时走 bridge，故意不走 UAC。
- 提权路径单独用 `ELEVATION_TIMEOUT = 120s`（原 `COMMAND_TIMEOUT` 只有 8s，等用户点 UAC 不够）。
- 新增 `get_bridge_status` 命令 + i18n `bridgeConnected/bridgeUnavailable`，服务弹窗中展示。
- 冒烟测试：临时写了 `cpum-core/tests/smoke_ipc_tmp.rs`（起 serve 线程 + Ping/错误 token/set_affinity）
  验证通过后删除 —— 管道名固定，留着会和本机真实服务抢管道，不适合常驻。

## 本机环境备忘

- Bash 工具在此环境不可用（缺 coreutils，连 `ls`/`dirname` 都 command not found），一律用 PowerShell。
- PowerShell 不回传 stdout，需要 `| Out-File <path> -Encoding utf8` 再用 Read 读取。
- 可用 `C:\Users\eason\AppData\Local\tauri\NSIS\makensis.exe` 单独编译一个最小 .nsi 来校验
  `installer-hooks.nsh` 语法，比跑完整 `tauri build` 快得多。
